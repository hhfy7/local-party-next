# Monorepo 新手指南 (前端视角)

你好！这份文档是专门为你准备的。Monorepo (单体仓库) 听起来很吓人，但理解了它的核心逻辑后，你会发现它其实是为了**偷懒**和**整洁**而发明的。

## 1. 什么是 Monorepo？

想象你正在装修两套房子：

- **房子 A** (你的 Web 前端项目)
- **房子 B** (你的后端 API 项目)

### 以前的做法 (Polyrepo / 多仓库)

你把两套房子建在城市的两个不同角落（两个完全独立的 GitHub 仓库）。

- 如果你买了一套很好用的“螺丝刀工具箱”（比如一个处理日期的代码库），你需要去房子 A 买一套，再去房子 B 买一套。
- 如果你定义了一个“家庭成员名单格式”（TypeScript 类型定义），你在房子 A 写了一遍，还得复制粘贴到房子 B。如果格式变了，你得跑两个地方去改。

### 现在的做法 (Monorepo / 单仓库)

你建了一栋**大别墅**，里面有两个房间：

- **房间 A**: 前端
- **房间 B**: 后端
- **客厅 (Shared)**: 公共区域

现在：

- **工具共享**: 螺丝刀放在客厅，房间 A 和 B 的人随时都能拿去用（比如 `eslint` 配置）。
- **代码共享**: “家庭成员名单”写在客厅的黑板上（`packages/shared`），大家抬头就能看到，改一次，两边都生效。

## 2. 我们的目录结构

```text
local-party-next/          <-- 大别墅 (根目录)
├── package.json           <-- 别墅的物业管理规定 (定义了怎么启动、有什么公共工具)
├── pnpm-workspace.yaml    <-- 房间门牌号登记 (告诉 pnpm 哪里是房间)
└── packages/              <-- 居住区
    ├── client/            <-- 前端房间 (React)
    ├── server/            <-- 后端房间 (Node/Express)
    └── shared/            <-- 客厅 (存放公共的 TypeScript 类型、常量)
```

## 3. 为什么用 pnpm？

`pnpm` 是这个别墅的高级管家。

- **省空间**: 他不会给每个房间都买重复的家具。如果大家都用 React，他只会在仓库里存一份，然后通过“传送门”（软链接）让大家都能用。
- **工作空间 (Workspaces)**: 他能识别 `packages/` 里的结构，让你在一个目录下就能控制所有房间。

## 4. 常用命令解析

你在根目录 `package.json` 里看到的命令：

- **`"dev": "pnpm -r --parallel run dev"`**
  - `pnpm`: 呼叫管家。
  - `-r` (recursive): **递归**。意思是“对所有房间（client, server...）广播”。
  - `--parallel`: **并行**。意思是“不要一个一个来，大家同时开工！”（不然前端启动了卡住，后端就永远没法启动了）。
  - `run dev`: 执行每个房间原本设定的 `dev` 任务。

- **`"build": "pnpm -r run build"`**
  - 让所有房间同时开始打包装修，准备发布。

- **`"lint": "pnpm -r run lint"`**
  - 让所有房间同时进行大扫除（代码检查）。

## 5. 开发时的注意事项

1.  **安装依赖**:
    - 如果你想给前端装个按钮库：`pnpm add button-lib --filter client` (指定给 client 房间)。
    - 如果你想给整个别墅装个工具（比如 eslint）：`pnpm add eslint -w -D` (`-w` 代表 workspace root，根目录)。

2.  **修改共享代码**:
    - 如果你修改了 `packages/shared/src/types.ts`，通常前端和后端会自动感知到变化（因为它们直接引用了文件）。
