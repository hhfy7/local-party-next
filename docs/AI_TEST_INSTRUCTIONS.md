> **用途**: 本文档专为 AI Agent 设计。如果你是被召唤来进行测试的 AI，请严格遵循以下指引。
> **最后更新**: 2026-01-23

## 1. 快速开始 (Quick Start)

**不要安装任何东西！** 环境已经配置好了。直接运行以下命令：

```bash
# 运行所有测试 (Headless 模式 跳过 p2p相关的)
npx playwright test --grep-invert "P2P" 
# 运行所有测试
npx playwright test 

# 运行特定测试文件
npx playwright test e2e/specs/lifecycle.spec.ts
npx playwright test e2e/specs/mobile-layout.spec.ts
npx playwright test e2e/specs/p2p.spec.ts
npx playwright test e2e/specs/video-controls.spec.ts
npx playwright test e2e/specs/mobile-safe-area.spec.ts

# 调试模式 (带浏览器界面)
npx playwright test --ui
```

## 3. 重要：测试失败时的处理原则

### 3.1 核心原则

**当测试失败时，AI 应该遵循以下优先级**:

1. **第一步**: **分析失败原因** - 确定是代码问题还是测试问题
2. **第二步**: **只改测试，不改功能** - 如果功能正常但测试失败，只修改测试代码
3. **第三步**: **保留功能，适配测试** - 确保产品功能不受影响

### 3.2 常见失败场景与处理

| 失败类型         | 症状                           | 处理方案                   | 是否修改功能代码 |
| ---------------- | ------------------------------ | -------------------------- | ---------------- |
| **选择器失效**   | `getByText` 找不到元素         | 更新测试中的文本选择器     | ❌ 不改功能      |
| **UI 结构调整**  | 元素位置变化导致截图失败       | 更新测试选择器或截图基准   | ❌ 不改功能      |
| **样式微调**     | 颜色、间距变化导致视觉测试失败 | 更新基准截图或调整像素容差 | ❌ 不改功能      |
| **新增功能**     | 新元素遮挡了测试元素           | 更新测试选择器，避开新元素 | ❌ 不改功能      |
| **文本内容变更** | 按钮文字、提示文字变化         | 更新测试中的匹配文本       | ❌ 不改功能      |
| **布局调整**     | 元素顺序、结构变化             | 更新测试选择器逻辑         | ❌ 不改功能      |
| **真实功能 Bug** | 功能确实无法正常工作           | 记录问题，与用户确认后修复 | ✅ 可改功能      |

### 3.3 测试失败分析流程

**当测试失败时，按以下步骤分析**:

1. **查看错误信息**: 确定失败的具体位置和原因
2. **手动验证功能**: 打开浏览器手动测试相关功能是否正常工作
3. **对比失败类型**: 参考上表判断是哪种类型的失败
4. **制定修复方案**:
   - 如果是测试代码问题 → 只修改测试文件
   - 如果是功能代码问题 → 与用户确认后再修改
5. **执行修复**: 优先修改测试，确保测试能准确验证功能

### 3.4 禁止行为

**❌ 绝对禁止**:

- 不要因为测试失败就回滚或修改正常的产品功能
- 不要为了让测试通过而破坏用户体验
- 不要修改核心业务逻辑来适应测试
- 不要在未确认的情况下修改功能代码

**✅ 推荐做法**:

- 优先更新测试选择器、断言逻辑
- 调整测试的等待时间、超时设置
- 更新视觉测试的基准截图
- 优化测试的稳定性，而不是修改功能

## 4. 常见问题 (Troubleshooting)

- **HTTPS 错误**: 如果遇到 SSL 报错，请检查 `playwright.config.ts` 中的 `ignoreHTTPSErrors: true`。
- **超时 (Timeout)**:
  - 建房/进房如果超时，通常是因为 DOM 选择器变了。
  - 请检查 `e2e/fixtures/room-helper.ts` 中的 `getByText` 或 `getByRole` 是否与代码匹配。
- **文件注入失败**: 确保 `e2e/test-assets/small-video.mp4` 存在。
- **P2P 失败**: 如果 `p2p.spec.ts` 失败，首先检查是否开启了 VPN (会导致 ICE 连接失败)。
- **视频控制失败**: 如果 `video-controls.spec.ts` 失败，检查方向键是否绑定到视频 seek 功能，以及是否有聊天反馈消息。
- **移动端安全区域失败**: 如果 `mobile-safe-area.spec.ts` 失败，检查 `pb-safe` 类是否正确应用，以及聊天面板布局。

## 5. 编写新测试指南 (Guide for AI)

如果你需要编写新测试，请：

1. **复用 Fixture**: 始终使用 `RoomHelper` 类来处理建房和进房。
2. **移动端测试**: 在 `test.use()` 中指定 `...devices['Pixel 5']` (避免下载 WebKit)。
3. **保持清理**: 测试结束后不需要手动删除房间，Server 重启会自动清理。
4. **语言一致性**: 所有测试步骤、控制台输出、注释都应该使用中文。
5. **失败处理**: 遵循第3节的处理原则，优先修改测试而不是功能。

## 6. 功能开发后的测试更新

当你帮助用户开发新功能时：

### 6.1 开发完成后

1. **运行所有测试**: `npx playwright test`
2. **分析失败原因**: 根据第3节的流程分析
3. **更新相关测试**: 只修改受影响的测试文件
4. **验证修复**: 确保所有测试通过

### 6.2 新增功能的测试

1. **评估测试必要性**: 判断新功能是否需要自动化测试
2. **编写测试**: 如果需要，参考现有测试模式编写
3. **记录测试**: 将新测试添加到上文的测试案例表中
4. **更新文档**: 更新本文档的相关部分

### 6.3 测试记录模板

当添加新测试时，请使用以下模板记录：

```markdown
| **TC-XX** | **功能名称**<br>功能描述和注意事项。 | `e2e/specs/xxx.spec.ts` | ✅ 状态 |
```

## 7. 特殊测试说明

### 7.1 P2P 测试特殊处理

- **环境要求**: 需要良好的网络环境，避免 VPN
- **失败容忍**: 由于网络因素，偶尔失败可以接受
- **跳过选项**: 在 VPN 环境下可跳过：
  ```bash
  npx playwright test --grep-invert "P2P"
  ```

### 7.2 移动端测试

- **设备模拟**: 使用 Pixel 5 设备参数
- **安全区域**: 特别注意 `pb-safe` 类的应用
- **视觉回归**: 首次运行需要生成基准截图

### 7.3 视频控制测试

- **键盘事件**: 确保方向键事件正确绑定
- **聊天反馈**: 验证跳转后是否有系统消息
- **时间精度**: 允许 ±1 秒的时间误差
